## Summary

Package metadata is bumped to `0.4.4` and remote deploy/bootstrap commands no
longer force SSH port `22022` when `--ssh-port` is omitted.

## Why

SSH aliases can already define the correct user, host, identity, and port. When
Ophelia always passed `-p 22022`, aliases that intentionally use the default
SSH port could connect with `ssh <alias>` but fail during Ophelia's rsync-based
remote staging step.

## Changed Areas

- `src/ophelia/commands/deploy.py`: makes `--ssh-port` optional and documents
  that omission uses SSH config/default behavior.
- `src/ophelia/commands/bootstrap_host.py`: matches deploy's optional SSH port
  behavior.
- `src/ophelia/remote.py`: omits `ssh -p ...` for both rsync and shell commands
  unless an explicit port is provided.
- `tests/test_remote.py`: covers omitted-port alias behavior and explicit-port
  behavior for rsync and SSH commands.
- `pyproject.toml`, `README.md`, `docs/ROADMAP.md`, and this changelog index:
  record the `0.4.4` release.

## Contract Impact

Omitting `--ssh-port` now honors SSH config and OpenSSH defaults. Operators who
need a non-default port can still pass `--ssh-port <port>`.

## Safety Impact

This only changes connection argument construction for remote staging and
bootstrap. It does not alter rendered app bundles, Caddy config, env handling,
or runtime apply semantics.
