## Summary

Package metadata is bumped to `0.4.3` and shared Caddy reloads now guard
against managed static roots collapsing when `OPHELIA_STATIC_ROOT` is missing
from the reload environment. Version reporting also prefers source checkout
metadata when `./cli/ship` is run from a checkout with stale editable-install
metadata.

## Why

Static-site deploys use `{$OPHELIA_STATIC_ROOT}` in the shared Caddy snippets.
If Caddy is reloaded without the envfile, active routes can point at
`/<app>/current` instead of the runtime static release directory. That produces
valid TLS with HTTP 404 responses for every page in the static app.

## Changed Areas

- `src/ophelia/caddy_manager.py`: adapts Caddy with `/etc/caddy/env` before
  reload and refuses to reload when managed static roots expand to collapsed
  paths.
- `src/ophelia/runtime.py`: uses the envfile-aware shared Caddy reload path
  after apply, including when the shared Caddy env file changed.
- `tests/test_caddy_manager.py`: covers the collapsed-root guard and verifies
  the reload command keeps envfile diagnostics.
- `tests/test_apply_safety.py`: covers Caddy env changes without recreating the
  shared Caddy container.
- `src/ophelia/version.py` and `src/ophelia/self_test.py`: report source
  checkout versions from `pyproject.toml` when the checkout is the active CLI
  code path.
- `pyproject.toml`, `README.md`, `docs/ROADMAP.md`, and this changelog index:
  record the `0.4.3` release.

## Contract Impact

The package version is now `0.4.3`. Shared Caddy reload behavior is stricter:
reloads fail closed if a managed static root would be applied without
`OPHELIA_STATIC_ROOT`.

## Safety Impact

This patch avoids recreating the shared Caddy container for Caddy env changes
and prevents a bad reload from replacing the active Caddy config with collapsed
static roots.
