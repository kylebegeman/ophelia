## Summary

Prepare Ophelia 0.5.0 as the first release on the accepted platform direction.
The release adds strict boundary validation, secure filesystem mutation,
immutable operation staging, the authoritative SQLite operation journal,
recoverable execution, truthful static activation and rollback, and executable
Forge product-operation bundles with reviewed compatibility locks.

## Why

The changes since 0.4.4 establish new execution and interoperability contracts.
They are materially larger than a patch and need one pinned version that Lumen
can install, verify, and operate consistently across preflight and deploy.

## Changed Areas

- `src/ophelia/domain/`, `src/ophelia/execution/`, and
  `src/ophelia/validation/`: canonical contracts, journaled execution,
  recovery, secure staging, and boundary validation.
- `src/ophelia/filesystem.py`: descriptor-relative, atomic filesystem
  primitives used by trusted mutations.
- `src/ophelia/product_bundle.py`, `product_execution.py`, and
  `product_recovery.py`: validated Forge bundle consumption, replicated process
  execution, lifecycle hooks, recovery, traffic, backup, and receipts.
- `fixtures/compatibility/forge-products.json`: explicit reviewed Forge
  interoperability lock.
- Platform strategy, architecture, capability, roadmap, and release docs.
- Package metadata and README version reporting.

## Contract Impact

The package version becomes `0.5.0`. New kernel and product-operation JSON
surfaces are pre-1.0 contracts. Valid v1 manifests remain supported; the
journaled executor does not silently reinterpret them as future manifest v2.

## Safety Impact

Mutation paths added in this release are confirmation-bound, journaled,
idempotent, fenced, recoverable, and verified before success is committed.
Invalid artifacts, paths, identifiers, and tampered plans fail closed. The
release does not itself authorize a production deploy or host migration.
